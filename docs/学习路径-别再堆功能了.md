# 别再堆功能了：一份真正能记住的学习路径

> 写给「学了好几个还是迷」的状态。
> 这份文档**不含任何新功能**，只解决「怎么记住、怎么不迷」。

---

## 一、先诊断：你为什么忘

不是脑子问题，是**学习方式的三处结构性问题**：

| 问题 | 具体表现 | 为什么会忘 |
|---|---|---|
| **知识是堆叠的，不是串起来的** | 今天学 GET/POST，明天加 RESTful，后天加 Swagger，再加 MyBatis-Plus | 每块知识都挂不到一根主线上，像往抽屉里乱塞东西，找不到就以为忘了 |
| **一直是「读 + 抄」，没「写 + 跑断」** | 代码是看会/抄会的，编译通过就过 | 看懂 ≠ 能写。考场上想不起来的都是没亲手写过的 |
| **一开始就上了新版本 + 多组件** | Boot 4.1.1 + MyBatis-Plus 3.5.17 + springdoc 3.x | 网上 95% 的中文教程是 Boot 2/3 的写法，你一搜就对不上，越搜越乱 |

第 3 条特别值得说：**这轮我们踩的坑几乎全是「版本差异」，不是「概念没懂」** ——
`\u` 转义、GB2312 编码、`extension.service` 包名迁移、H2 控制台被移除……
这些是**查资料的体力活**，学不到任何原理，却消耗了你大量信心。
**你的迷茫有相当一部分是环境造成的，不是你的问题。**

## 二、只留一根主线：一次 HTTP 请求的一生

前面所有知识点，全部能挂在这一根线上。看 `一张图看懂请求流转.md`，一句话版：

```
HTTP 请求 → 拦截器 → 找处理方法 → 参数绑定 → Controller → Service → Mapper
         → SQL 执行 → 结果映射 → 转 JSON → 返回
```

**检验标准**：随便给你一个报错，你能说出「它卡在第几环」吗？
- 404 卡在「找处理方法」
- 500 卡在「Controller/Service/Mapper」
- 401 卡在「拦截器」
- 字段为 null 卡在「结果映射」

能这么定位，你就通了。**这比多会三个注解有用得多。**

## 三、核心只有 20%：这张表背下来就够用了

其余都是这 20% 的排列组合。

### 3.1 接收请求（4 个注解）

| 场景 | 注解 | 参数长什么样 |
|---|---|---|
| 查数据 | `@GetMapping("/users/{id}")` | 路径里 `/users/1` → `@PathVariable Long id` |
| 查列表 + 过滤 | `@GetMapping("/users")` | URL 上 `?age=20` → `@RequestParam Integer age` |
| 新增 | `@PostMapping("/users")` | JSON body → `@RequestBody UserDTO dto` |
| 改 / 删 | `@PutMapping` / `@DeleteMapping` | 同上 |

**一句话记**：**GET 的参数在 URL 上，POST 的参数在 body 里。**

### 3.2 返回响应（3 种）

```java
return "文本";                              // 直接返回，最简单
return userDeptVO;                          // 返回对象 → 自动变 JSON
return ResponseEntity.ok(...)               // 需要控制状态码时用（201/204/404）
```

`@RestController` = 所有方法的返回值都自动转 JSON，不用一个个加注解。

### 3.3 三层结构（记住各层「不许干什么」）

| 层 | 只允许干 | 不许干 |
|---|---|---|
| Controller | 收参数、调 Service、包返回值 | ❌ 写 SQL、写业务计算 |
| Service | 业务逻辑、拼条件 | ❌ 直接写 SQL |
| Mapper | 定义查什么数据 | ❌ 写业务判断 |

**为什么分层？** 因为要能单独测、单独改。学习阶段记不住没关系，
记「Controller 不写 SQL」这一条就够用。

### 3.4 数据库三件事

```java
// ① 单表：BaseMapper 白拿
userMapper.selectById(1L);       // 查一个
userMapper.insert(user);         // 插一条

// ② 分页：传 Page 进去
Page<SysUser> page = new Page<>(1, 5);   // 第 1 页，每页 5 条
userMapper.selectPage(page, wrapper);    // page 被填好 records 和 total

// ③ 多表：写 XML
// resources/mapper/XxxMapper.xml 里写 JOIN，列名用 AS 起同名别名
```

**分页唯一要记住的坑**：`PaginationInnerInterceptor` 不注册，分页**不报错但失效**。
所以每次写完分页，**必须看一眼控制台 SQL 里有没有 LIMIT**。

## 四、动手练习：30 分钟，从零写一个「收藏夹」接口

> 这是这份文档唯一要求你做的事。
> **规则：全程不许翻前面三个教程文档，只许查上面第三节那张表。**
> 卡住了就卡 5 分钟，5 分钟后卡住的地方，就是你真正的缺口。

### 目标接口

| 方法 | 路径 | 干什么 |
|---|---|---|
| GET | `/api/bookmarks` | 分页查收藏列表 |
| POST | `/api/bookmarks` | 新增一条收藏 |

### 表设计（自己写 `schema.sql` 里加，或新建一张）

```sql
CREATE TABLE bookmark (
    id      BIGINT      NOT NULL AUTO_INCREMENT,
    title   VARCHAR(50) NOT NULL,
    url     VARCHAR(200),
    PRIMARY KEY (id)
);
```

### 六步，每步都停下验证

| 步骤 | 写什么 | 验证方式（必须跑） |
|---|---|---|
| 1 | `Bookmark` 实体（POJO + 两个注解） | `.\mvnw.cmd -q compile` 过 |
| 2 | `BookmarkMapper extends BaseMapper<Bookmark>` | 同上（注意要不要 `@Mapper`） |
| 3 | `BookmarkService` + `Impl` | 同上 |
| 4 | `BookmarkController`，先只写 GET 分页 | 启动后用 curl 调通，看控制台**有没有 LIMIT** |
| 5 | 加 POST 新增（要返回 201） | curl POST 一条，再 GET 列表看有没有进去 |
| 6 | 给两个方法加 `@Operation` | 打开 `/swagger-ui.html` 看有没有出现 |

**第 4 步是分水岭**：能自己调通分页，说明你真正会了；调不通，就对着那张图找卡在第几环。

### 加分：故意把它弄坏（这一步最值钱）

学得牢的人不是没踩过坑，是**主动踩过**。修好之后再做这三件事：

1. 把 `MybatisPlusConfig` 里的 `@Configuration` 注释掉 → 看分页怎么个「不报错但失效」；
2. XML 里故意把 `AS deptName` 删掉 → 看哪个字段变 null；
3. 请求时**不带** `token` 头 → 确认是 401 而不是 404。

**弄坏 → 观察现象 → 修好**，走完这一遍，这三个知识点你这辈子忘不掉。

## 五、明确「现在不用学」的清单（减少焦虑）

学习最大的消耗是「觉得自己什么都不会」。以下东西**现在完全不碰**：

- ❌ 多数据源、读写分离、分库分表
- ❌ 事务传播机制（`@Transactional` 的 7 种传播行为）
- ❌ MyBatis 一级/二级缓存
- ❌ 乐观锁、逻辑删除（知道有这两个东西即可）
- ❌ 网关、注册中心、微服务
- ❌ 自己写 MyBatis 插件、拦截器原理

**这些等你手上有真实需求时再学，那时学一遍就会。** 现在学只会增加负担。

同样，下面这些**已经会了，不用再学**：
GET/POST 的区别、RESTful 路径规范、Swagger 怎么看、分页怎么传参。

## 六、关于环境：一个真心建议

**如果你是初学，建议另开一个 Boot 3.x 的学习项目。**

原因很直接：

| | Boot 4.1.1（当前项目） | Boot 3.x |
|---|---|---|
| 中文教程匹配度 | 极低，搜到的都对不上 | 铺天盖地，几乎都能直接用 |
| 包名 | MyBatis-Plus 3.5.17 迁移了包名 | `extension.service` 等老包名有效 |
| 依赖名 | `spring-boot-starter-webmvc` | `spring-boot-starter-web` |
| 踩坑性质 | 大量版本差异坑，学不到原理 | 坑少，注意力能放在概念上 |

学习阶段，**把「查资料的成本」降到最低比用最新版本重要得多**。
当前项目继续留着当「踩坑记录」很好，但别在这里练基础。

如果决定这么做，可以这样起步：

```powershell
# 用 start.spring.io 生成一个 Boot 3.5.x 的项目
# 依赖只勾：Spring Web、MyBatis Framework、H2、Lombok（可选）
# 别的什么都不要勾
```

**先把「一次请求走完全程」这一件事做透**，再逐步加东西。

## 七、怎么才算真的学会了

不要用「我看懂了」当标准，用这三条：

1. **能默写**：关掉所有文档，从零写出一个能跑通的查询接口（实体→Mapper→Service→Controller）；
2. **能定位**：给你一个 404 / 500 / 401 / 字段为 null，你能说出卡在上面那张图的第几环；
3. **能讲清**：向别人解释「为什么分页插件不注册就不报错但失效」

三条都过，这一块就翻篇了，可以放心学下一块。
**一条没过就别加新功能** —— 这就是你之前会迷的根因：旧账没结清就开新账。
