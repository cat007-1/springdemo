# 一张图看懂：你的请求到底走了哪些代码

把这张图记住，前面学的所有东西就都有位置了。

---

## 你只需要记住这一条流水线

```
你在浏览器/curl 里敲：
  GET http://localhost:8081/api/db/users/page?current=1&size=5
  请求头 token: 123456
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ ① Tomcat（Spring Boot 内置）                             │
│    监听 8081，把 HTTP 文本解析成 request 对象             │
│    —— 这一步你不用管，配置里写 server.port=8081 就是在说它 │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ ② 拦截器 LoginInterceptor（WebMvcConfig 里注册）          │
│    检查 request 头里有没有 token                          │
│    没有 → 直接返回 401，后面所有代码都不执行              │
│    —— 你测「无 token 返回 401」测的就是这一层              │
└─────────────────────────────────────────────────────────┘
        │ 放行
        ▼
┌─────────────────────────────────────────────────────────┐
│ ③ DispatcherServlet 找「谁来处理这个请求」                │
│    路径 /api/db/users/page + 方法 GET                     │
│    → 匹配到 DbQueryController.pageUsers()                │
│    —— @GetMapping("/users/page") 就是这张对照表的条目      │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ ④ 参数绑定：把 URL 上的东西变成 Java 变量                 │
│    ?current=1&size=5  →  long current=1, long size=5     │
│    —— @RequestParam 就是在告诉 Spring 怎么转              │
│    —— 如果是 POST 的 JSON，这一步由 @RequestBody + Jackson │
│       把 JSON 反序列化成对象（那时候你会写 @RequestBody）  │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑤ Controller（DbQueryController）                        │
│    只做三件事：收参数 → 调 Service → 包装返回值            │
│    绝不在 Controller 里写 SQL、写业务计算                  │
└─────────────────────────────────────────────────────────┘
        │ 调用
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑥ Service（SysUserServiceImpl）                          │
│    业务逻辑：拼查询条件、决定调哪个 Mapper 方法            │
│    new Page<>(current, size)  ← 分页参数从这里进去        │
└─────────────────────────────────────────────────────────┘
        │ 调用
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑦ Mapper（SysUserMapper 接口）                            │
│    你只写接口和 SQL，实现类是 MyBatis 在运行时生成的       │
│    简单单表 → MyBatis-Plus 的 BaseMapper 自动生成 SQL     │
│    多表关联 → 读 resources/mapper/SysUserMapper.xml       │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑧ 分页拦截器 PaginationInnerInterceptor（MybatisPlusConfig）│
│    发现方法第一个参数是 IPage，于是：                      │
│      先执行一条 SELECT COUNT(*) 拿到 total                │
│      再给原 SQL 末尾拼上 LIMIT ? OFFSET ?                 │
│    —— 这就是「不注册插件分页会静默失效」的原因            │
└─────────────────────────────────────────────────────────┘
        │
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑨ HikariCP 连接池 → H2 数据库真正执行 SQL                 │
│    控制台打印的 ==> Preparing: 就是这一层的输出           │
└─────────────────────────────────────────────────────────┘
        │ 结果集 ResultSet
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑩ 结果映射：把数据库的「行 + 列」变成 Java 对象            │
│    行 → UserDeptVO 对象，列 → 对象属性                    │
│    列名 dept_name 怎么对上属性 deptName？                 │
│      → XML 里写 AS deptName（别名同名，最稳）             │
└─────────────────────────────────────────────────────────┘
        │ 一层层返回上去
        ▼
┌─────────────────────────────────────────────────────────┐
│ ⑪ Jackson 把对象转成 JSON                                │
│    Controller 返回 Map/对象 → @RestController 自动转 JSON  │
│    —— 返回 record 也是在这一步被转的                      │
└─────────────────────────────────────────────────────────┘
        │
        ▼
    HTTP 200 + JSON 文本 → 回到你的浏览器
```

## 你学过的四个东西，分别插在哪一环

| 你学的东西 | 插在图的哪一环 | 一句话记住 |
|---|---|---|
| GET/POST 怎么发 | ① 和 ④ | 方法决定动作，参数位置决定注解 |
| RESTful | ③ 的路径设计 | 路径是名词，动作用 HTTP 方法表达 |
| Swagger | 独立旁路，不参与请求 | 它只是**读**你的注解，生成一份文档网页 |
| MyBatis-Plus | ⑦⑧⑩ | Mapper 写 SQL，插件改 SQL，映射转对象 |

**Swagger 是唯一不在流水线上的东西** —— 它不处理请求，只是把你 `@Operation` 那些注解
收集起来渲染成一个网页。很多人迷糊就是因为把它和业务代码混在一起理解了。

## 出问题时，按这张图从下往上查

这是这张图最实用的地方：**报错时你该看哪一层，是确定的。**

| 症状 | 卡在哪一环 | 去看什么 |
|---|---|---|
| 连不上、Connection refused | ① | 服务起了吗？`netstat -ano \| Select-String ":8081"` |
| 401 未登录 | ② | 请求头带 `token` 了吗？ |
| 404 Not Found | ③ | 路径写对没？看 Swagger 里列出的真实路径 |
| 400 Bad Request | ④ | 参数类型/JSON 格式对不对 |
| 415 Unsupported Media Type | ④ | `Content-Type` 头写了吗？ |
| 500 报错、日志有堆栈 | ⑤⑥⑦ | 抄最后一行的 `Caused by` |
| 分页返回全部数据、total 不对 | ⑧ | 分页插件注册了吗？看 SQL 里有没有 LIMIT |
| 查出来某字段是 null | ⑩ | SQL 列名和对象属性名对不上 |
| 中文乱码 | ⑪ | 与 HTTP 无关，先看响应字节 |
| 编译「找不到符号」 | 代码本身 | 先查 import 和依赖版本，别改逻辑 |

**「404 还是 500」是最有价值的区分**：
404 说明**根本没进你的代码**（路径没匹配上）；500 说明**进了你的代码但抛异常了**。
只看这一个信息，排查方向就差一倍。

## 自测：能答对这 5 题，你就是真懂了

先别翻文档，凭印象答：

1. 我写了 `@GetMapping("/hello")`，为什么浏览器敲 `/hello?nickname=Tom` 就能拿到 `nickname`？
   （提示：第 ④ 环发生了什么）
2. 我把 `MybatisPlusConfig` 整个删掉，`/api/db/users/page` 会返回什么？会报错吗？
   （提示：第 ⑧ 环，这题最容易答错）
3. 前端说「接口返回 404」，你怎么在 30 秒内判断是路径错了还是数据不存在？
4. `UserDeptVO` 里的 `deptName`，为什么在 `SysUser` 实体里找不到这个字段？
5. `@Mapper` 这个注解，如果我不写会怎样？为什么？

答不上来很正常 —— 答不上来的那一题，就是你现在真正的缺口，
**对着上面那张图找到对应环节，只补那一环**，不要重头再学一遍。
